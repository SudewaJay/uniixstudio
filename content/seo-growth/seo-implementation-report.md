**Added**
- `content/blog/<slug>.mdx` × 5: article source in the established editorial frontmatter format (`layout: "editorial"`, `seoTitle`, `keyTakeaways`, `relatedServices`, `relatedPosts`, CTA fields, FAQs, `faqSchema: false`).

**Changed**
- `components/ContactForm.tsx`: sends a GA4 `generate_lead` event on successful submission, and stores the referring same-site page in the enquiry's `source` field (e.g. `/contact/ ← /blog/payment-gateway-sri-lanka-website/`).
- `components/ThirdPartyScripts.tsx`: one delegated click listener inside the existing GA4 script, which sends `contact_click` with `method` = whatsapp, phone or email. It only loads when GA4 is configured.
- `components/blog/EditorialArticle.tsx`: styles for fenced code (`pre`, scrolls inside its own box) and inline `code`. Before this, a code block overflowed the article column. This also improves existing posts that contain code.
- `scripts/cms/seed.ts`: new `SEED_BLOG_SLUGS=a,b,…` mode that seeds only the named posts and nothing else (see below for why).

No routes, dependencies or existing content were changed.

## 4. Sitemap and indexing

- The sitemap is generated from the CMS (`app/sitemap.ts`). All five URLs appeared in `/sitemap.xml` on the local build. Nothing needs to be edited.
- Posts with a future `publishDate` are hidden from pages, the sitemap and RSS until their date. The one-hour CMS cache then surfaces them.
- `robots.txt` allows all crawlers, including AI crawlers, and disallows only `/admin/` and `/api/`.

## 6. How to publish (needs your go-ahead)

The live blog reads from the production Payload database. To publish:

1. Review and merge `feat/seo-growth-blogs` so the images in `public/blog/` and the code changes deploy to Vercel. Merging alone does **not** publish the posts.
2. Load the five posts into the production CMS with the targeted seed. It uses `DATABASE_URI` from `.env`, which points at production:

   ```bash
   SEED_DRY_RUN=1 SEED_BLOG_SLUGS=online-booking-system-sri-lanka,medical-lab-clinic-website-design-sri-lanka,payment-gateway-sri-lanka-website,multilingual-website-sinhala-tamil-english,lk-domain-registration-guide npm run cms:seed
   ```

   If the dry run reports 5 to create, run the same command without `SEED_DRY_RUN=1`.
3. Each post goes live on its `publishDate` (20 Oct to 17 Nov). To change a date, edit it in the CMS admin after seeding.

**Use the targeted mode on production.** A plain `npm run cms:seed` that creates any new post also re-applies `relatedPosts` from the MDX files to *every* existing post, which would overwrite related-post changes made in the CMS. `SEED_UPDATE_EXISTING=1` would overwrite everything editors have changed since the migration.

## 7. Limitations and assumptions

- Keyword volumes, difficulty and rankings were **not** available; topic selection is qualitative and the evidence is documented in `keyword-opportunities.md`.
- Third-party facts (PayHere fees, .lk prices, PDPA dates, Stripe and Shopify availability) were verified on 18 October 2026 and are dated in the copy. They need a quarterly re-check.
- The LK Domain Registry's own pages disagree on whether prices include VAT. The article says so rather than picking one.
- The articles describe St Luke's, CricBook, RentMyCar.lk, Wasana Drivers and Bilesma Natural using only facts already published in this repo's case studies. Claims inside those case studies (e.g. Lighthouse scores, Wasana's "< 1.2s") were not re-measured.
- The byline is "Uniix Studio". If a named, qualified person reviews the healthcare article, adding their name would strengthen it; no reviewer was invented.
